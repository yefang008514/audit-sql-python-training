## 一、业财核对

### 1.1 三单匹配（订单 / 收货单 / 发票）

**业务逻辑**：一笔采购业务应有采购订单（PO）、收货单（GRN）、供应商发票（Invoice）三单，数量与金额应互相勾稽。三单不匹配 = 潜在舞弊或差错（未收货先付款、发票超收货、无订单采购等）。

**数据准备**（三张表的关键字段）：

| orders 订单 | receipts 收货单 | invoices 发票 |
|---|---|---|
| po_no, supplier, material, qty, unit_price | grn_no, po_no, qty_received, recv_date | inv_no, po_no, amount, inv_date |

**匹配 SQL（核心逻辑）**：

```sql
WITH po AS (
  SELECT po_no, supplier, SUM(qty) AS po_qty, SUM(qty * unit_price) AS po_amt
  FROM orders GROUP BY 1, 2
),
grn AS (
  SELECT po_no, SUM(qty_received) AS grn_qty FROM receipts GROUP BY 1
),
inv AS (
  SELECT po_no, SUM(amount) AS inv_amt FROM invoices GROUP BY 1
)
SELECT po.po_no, po.supplier,
       po.po_qty, COALESCE(grn.grn_qty, 0)  AS grn_qty,
       po.po_amt, COALESCE(inv.inv_amt, 0)  AS inv_amt,
       CASE
         WHEN grn.po_no IS NULL THEN '异常：有订单无收货'
         WHEN inv.po_no IS NULL THEN '关注：已收货未收票（暂估）'
         WHEN inv.inv_amt > po.po_amt * 1.01 THEN '异常：发票金额超订单'
         WHEN grn.grn_qty > po.po_qty THEN '异常：超量收货'
         ELSE '正常'
       END AS 匹配结论
FROM po
FULL OUTER JOIN grn ON po.po_no = grn.po_no   -- FULL JOIN：单边存在的也抓出来
FULL OUTER JOIN inv ON po.po_no = inv.po_no;
```

**要点**：
- 用 `FULL OUTER JOIN` 而不是 `INNER JOIN`——审计关心的是**对不上的**。
- 实务中很难有统一的 po_no 贯通三单，常常要靠"供应商+物料+金额±容差+日期窗口"做模糊匹配，这时加 `ABS(a.amount - b.amount) <= 容差 AND ABS(a.date - b.date) <= N` 的匹配条件。
- 差异结果输出成 Excel 底稿，就是现成的《采购循环核对差异表》。

### 1.2 序时账与银行流水双向核对

**业务逻辑**：序时账中银行存款科目的发生额，应与银行对账单流水一一对应。**双向**核对：
- 正向：流水里的每笔收付，账上有没有记（防账外资金、挪用）
- 反向：账上记的每笔银行收付，流水里有没有（防虚假记账、体外循环）

```sql
-- 正向：流水有、账上无（金额+日期模糊匹配，容差可调）
SELECT b.*
FROM bank_flow b
LEFT JOIN journal j
  ON j.科目编码 LIKE '1002%'                    -- 银行存款科目
 AND ROUND(ABS(j.借方金额 - b.收入金额), 2) < 0.01
 AND ABS(b.交易日期 - j.日期) <= 3              -- 允许 3 天在途
WHERE j.凭证号 IS NULL AND b.收入金额 > 0;

-- 反向：账上有、流水无（把上面左右表互换即可）
SELECT j.*
FROM journal j
LEFT JOIN bank_flow b
  ON ROUND(ABS(j.贷方金额 - b.支出金额), 2) < 0.01
 AND ABS(b.交易日期 - j.日期) <= 3
WHERE j.科目编码 LIKE '1002%' AND j.贷方金额 > 0 AND b.流水号 IS NULL;
```

**要点**：
- 实务难点是**一对多/多对一**（一笔收款拆几笔记账、多笔合并付款），先 1:1 精确匹配，再对剩余差异做组合匹配。
- 核对结论按金额分层：大额差异逐笔查，小额差异汇总披露。
- 长期未达账项（在途超 30 天）单独列示——这是银行余额调节表的数字化版本。

## 二、JET 测试（Journal Entry Testing，分录测试）

**背景**：准则要求对所有会计分录测试（应对管理层凌驾内控之上的风险）。全量数据时代，用 SQL 对分录特征画像。常见测试点：

| # | 测试点 | SQL 思路 |
|---|---|---|
| 1 | 周末/非工作日记账 | `extract(isodow from 日期) IN (6, 7)` |
| 2 | 月末/年末集中记账 | 日期 = 月末前后 N 天，`last_day(日期)` |
| 3 | 整数大额分录 | `金额 % 10000 = 0 AND 金额 >= 100000`（整数=拍脑袋迹象） |
| 4 | 非工作时间录入 | `extract(hour from 录入时间) NOT BETWEEN 8 AND 18` |
| 5 | 异常科目组合 | 某科目组合在正常业务中不应出现（如"借：管理费用 贷：营业外收入"），用规则表 JOIN |
| 6 | 高频相同金额 | `GROUP BY 金额 HAVING COUNT(*) > N`，同一金额反复出现 |
| 7 | 冲销/红字分录 | 同一凭证正负金额互抵，或摘要含"冲销/调整" |
| 8 | 手工凭证 vs 系统凭证 | 按凭证来源字段筛选，手工凭证风险更高 |
| 9 | 特定人员集中制单 | `GROUP BY 制单人 ORDER BY COUNT(*) DESC` 看集中度 |
| 10 | 临界值分录 | 金额略低于审批权限（如 99999 vs 权限 100000）：`金额 BETWEEN 权限*0.9 AND 权限*0.999` |

```sql
-- 组合示例：把每个测试点作为一列标签，一张表出全部疑点画像
SELECT * FROM (
  SELECT 凭证号, 日期, 摘要, 制单人, 金额,
    CASE WHEN extract(isodow from 日期) IN (6,7) THEN 1 ELSE 0 END AS 周末记账,
    CASE WHEN 日期 >= last_day(日期) - 2 THEN 1 ELSE 0 END AS 月末集中,
    CASE WHEN 金额 % 10000 = 0 AND abs(金额) >= 100000 THEN 1 ELSE 0 END AS 整数大额,
    CASE WHEN 摘要 ~ '冲销|调整|更正' THEN 1 ELSE 0 END AS 冲销调整
  FROM journal
) t
WHERE (周末记账 + 月末集中 + 整数大额 + 冲销调整) >= 2   -- 命中 2 项以上重点核查
ORDER BY abs(金额) DESC;
```

> 注：DuckDB 还支持用 `QUALIFY` 直接过滤窗口函数结果（如 `ROW_NUMBER()`），但 CASE 标签列不算窗口函数，需像上面这样用子查询包一层再 WHERE。

## 三、SQL 大规模数据抽样

### 3.1 简单随机抽样

```sql
-- DuckDB：直接 TABLESAMPLE / reservoir 抽样
SELECT * FROM journal USING SAMPLE 100 ROWS;        -- 固定抽 100 行
SELECT * FROM journal USING SAMPLE 5 PERCENT;       -- 按比例抽 5%

-- 通用写法：随机排序取前 N
SELECT * FROM journal ORDER BY random() LIMIT 100;
```

### 3.2 货币单位抽样（MUS，金额成比例抽样）

审计最常用：金额越大的项目被抽中概率越高。

```sql
WITH cum AS (
  SELECT *, SUM(abs(金额)) OVER (ORDER BY 凭证号) AS 累计金额,
            SUM(abs(金额)) OVER () AS 总体金额
  FROM journal
),
params AS (
  SELECT 总体金额 / 100 AS 抽样间隔 FROM cum LIMIT 1   -- 抽 100 个样本
)
SELECT c.*
FROM cum c, params p
WHERE floor(c.累计金额 / p.抽样间隔) <> floor((c.累计金额 - abs(c.金额)) / p.抽样间隔);
-- 原理：每个抽样间隔的"刻度线"落在哪笔分录的累计区间内，就抽中哪笔
```

### 3.3 分层抽样

```sql
-- 大额全查 + 小额随机抽（注意：ORDER BY random() LIMIT 要包在子查询里，不能直接写在 UNION 分支上）
SELECT *, '重点全查' AS 抽样层 FROM journal WHERE abs(金额) >= 100000
UNION ALL
SELECT *, '随机抽样' AS 抽样层
FROM (SELECT * FROM journal WHERE abs(金额) < 100000 ORDER BY random() LIMIT 50) t;
```

## 四、自动化底稿 pipeline（综合案例）

以货币资金循环为例，一条命令出整套底稿：

```
python code/python/02_auto_workpaper.py
```

脚本做的事（当前版本输出 3 张表，双向核对和 MUS 抽样可照 `code/sql/` 里的 SQL 直接扩展进来）：
1. 读序时账 → 清洗入 DuckDB
2. SQL 汇总 → 科目汇总表、月度发生额表

这基本就是「逆行的狗」公众号里 CPAH 底稿小帮手类工具的底层逻辑：**模板与逻辑分离，取数标准化，输出自动化**。
