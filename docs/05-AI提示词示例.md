# 05 AI 提示词示例

> 定位：AI 是帮你写第一稿的实习生——**它负责快，你负责对**。所有 AI 生成的 SQL / Python / 正则，必须用小样本验证后再上生产数据。

## 一、通用提示词框架

一个能用的审计代码提示词，通常包含五个要素：

```
【角色】你是一名熟悉审计业务的资深数据分析师，精通 SQL（DuckDB/PostgreSQL 方言）和 pandas。
【任务】请实现：<一句话说清楚要做什么>
【数据】表名 journal，字段如下：凭证号(文本), 日期(date), 科目编码(文本), 借方金额(数值), 贷方金额(数值), 摘要(文本)。样例数据：……（贴 3 行）
【约束】金额单位为元；日期只取 2024 年度；结果按金额降序；不要使用窗口函数（客户环境是旧版 MySQL）。
【输出】只输出 SQL 代码和 3 行以内的逻辑说明。
```

要素越齐，返工越少。**贴 3 行样例数据**是性价比最高的一个动作。

## 二、正则表达式提示词

### 场景 1：从摘要里提取发票号码

```
请写一个正则表达式，从中文报销摘要中提取发票号码。
样例文本：
  "报销差旅费 发票号04437215 高铁票"
  "付办公用品款(发票：3300221330-001)"
  "无发票 快递费"
要求：
1. 发票号为 8 位数字，或 10 位数字+"-"+3 位数字的卷票格式；
2. 只匹配"发票号/发票："之后的号码，避免误匹配其他数字；
3. 用 Python re 写出提取代码，对每行样例输出提取结果和匹配/未匹配标记；
4. 给出你在 regex101 上验证过的测试用例（至少含 1 个应不匹配的干扰样例）。
```

参考产出（必须自己验证）：

```python
import re
pattern = r'发票[号：:]\s*[（(]?(\d{8}|\d{10}-\d{3})'
```

### 场景 2：识别银行账号 / 票据号

```
请写一个 PostgreSQL 的 regexp_replace 表达式，把摘要中连续 12~19 位的数字
（疑似银行账号）脱敏为前 4 位 + "****" + 后 4 位。
注意：8 位发票号、6 位日期不能被误伤。给出 5 个测试用例验证边界。
```

### 场景 3：清洗人名/公司名中的异常字符

```
客户名称字段混有以下脏数据：全角/半角括号混用、名称前后的空格和 Tab、
"（已注销）""【停用】"等状态标记。请给出一组 SQL regexp_replace 链式清洗规则，
每条规则注明：处理什么、为什么这样处理、可能的误伤风险。
```

## 三、数据清洗提示词

### 场景 4：让 AI 生成 pandas 清洗代码

```
你是资深审计数据分析师。我拿到了客户导出的序时账 Excel，问题如下：
1. 第 1~2 行是报表标题和导出人信息，第 3 行才是表头；
2. 每 50 行会重复出现一次表头行；
3. 金额列带千分位逗号，且有 "借/贷" 方向列，贷方金额是空的、金额都在"金额"列里用方向区分；
4. 日期列混有 "2024/1/5" 文本和 Excel 序列数两种格式；
5. 最后一行是"本页合计"。

请写一个 pandas 函数 clean_journal(path)，输出干净的 DataFrame：
凭证号、日期(date)、科目编码(str)、摘要、带符号金额（借正贷负）、月份(YYYY-MM)。
要求：每一步清洗都打印"处理前/后行数"；借贷不平的凭证号单独输出列表；
对无法解析的行不要静默丢弃，存进 errors.csv。
```

**要点**：把脏数据的**具体症状**列成清单，AI 才能对症下药；只说"帮我清洗数据"得到的代码一定不能用。

### 场景 5：清洗规则审查（反向使用）

```
下面是我写的序时账清洗代码（贴代码）。请从审计复核角度审查：
1. 哪些步骤可能误删有效数据？
2. 哪些静默失败（errors='coerce' / dropna）会让数据悄悄变少？
3. 给出改进建议和修改后的关键代码。
```

## 四、异常特征描述提示词

### 场景 6：把 SQL 疑点结果翻译成人话

```
你是审计项目经理。下面 SQL 查出了命中 JET 测试的疑点分录（贴 10 行结果，
含字段：凭证号、日期、摘要、制单人、金额、命中标签）。
请为每笔分录生成一句 50 字以内的"疑点描述"，格式：
"该分录于<周末/月末>由<制单人>录入，金额<金额>为整数大额，且摘要含'调整'字样，
建议核查<具体核查方向>。"
要求：语气客观，只陈述事实特征，不做定性结论（不写"舞弊""违规"）。
```

### 场景 7：生成数据分析维度的头脑风暴

```
我要对某制造业客户的销售循环做全量数据分析，已有数据：销售订单、出库单、发票、
收款流水、客户主数据。请列出 15 个可执行的数据分析点，每个写明：
分析目的（发现什么风险）、关联哪几张表、核心 SQL 逻辑一句话。
按"收入真实性/截止性/关联方/价格异常/退货"五类组织。
```

## 五、纪律与红线

1. **数据脱敏再上传**：客户名称、账号、金额（可按比例缩放）先脱敏；遵守所内数据合规要求。
2. **AI 输出必验证**：SQL 先在 100 行样本上跑，核对 3~5 笔手工算过的结果。
3. **逻辑要留痕**：把最终确认的提示词和代码一起存进底稿——别人才能复核你的 AI 是怎么用的。
4. **不让 AI 做判断**：AI 可以筛疑点、写代码、起草描述；"是否构成错报"永远是审计人员的判断。
